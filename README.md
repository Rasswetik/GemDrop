# GemDrop — Flask / Telegram Mini App

## Render

Проект запускается через `render.yaml` и Gunicorn. Обязательные переменные:

- `BOT_TOKEN` — токен Telegram-бота.
- `WEBAPP_URL` — на Render обычно берётся автоматически из `RENDER_EXTERNAL_URL`.
- `ADMIN_IDS` — Telegram ID администраторов через запятую.
- `SECRET_KEY` — генерируется Render.
- `TON_DEPOSIT_WALLET` — адрес TON-кошелька проекта, на который идут пополнения.
- `TON_NETWORK` — `mainnet` (по умолчанию) или `testnet`.
- `TONCENTER_API_KEY` — необязательно, но рекомендуется для стабильной проверки TON-транзакций.
- `PORTAL_AUTH` — необязательно. Authorization Portal Market можно также сохранить из админ-панели; он хранится в БД/диске.

## Что изменено

- Webhook `/start` больше не ждёт второй HTTP-запрос к Telegram: метод `sendMessage` возвращается прямо в webhook-ответе.
- Portal Market: постоянный ключ, журнал импорта, все коллекции и цены с точностью до 0.01 TON.
- Новый экран загрузки с `static/gifs/shard.gif` и прогрессом.
- Mines: SVG-алмазы, случайная кнопка `?`, новый нижний интерфейс, сокращения `k/m/b x`, корректный баланс в шапке.
- Инвентарь: 3 подарка в ряд, карточка подарка, продажа в баланс, просмотр моделей Portal перед будущим выводом.
- Админка: пользователи, Portal, общий RTP, заготовка раздела выводов.
- TON Connect: подключение кошелька, создание транзакции и серверная проверка входящего платежа через TON Center API перед зачислением.

## RTP

RTP задаётся как общий коэффициент для новых раундов (80–100%), сохраняется в каждом раунде и виден пользователю. Персональная скрытая подкрутка вероятностей по депозитам или проигрышам не используется.

## TON

Баланс не зачисляется только по ответу браузера. После отправки TON сервер ищет входящую транзакцию на `TON_DEPOSIT_WALLET` с совпадающими отправителем и суммой и защищается от повторного использования одного transaction hash.
